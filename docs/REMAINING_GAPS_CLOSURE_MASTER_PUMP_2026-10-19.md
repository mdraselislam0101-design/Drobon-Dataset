## 3. Gaps closed with evidence

### 3.1 Unreadable detector prose — regex interpolated into sentences (200 SAST rules)

**Defect.** `{sink}` in rule/pattern/record/remediation templates was filled with the cell's
regex literal after unescaping, producing text such as
`In c, bprintfs*(s*[A-Za-z_]w*s*) interprets a variable as format text.`
Measured: **200 of 792 SAST rules** and **204 records** carried regex noise.

**Fix.** `displaySink()` in the generator uses a clean identifier when the literal is one,
otherwise the first declared positive example (`printf(userstr)`); secrets literals are left
untouched (they are fixture placeholders, not regexes). `test-assets` now rejects
`[A-Za-z]s*(`, `[A-Za-z]_`, `)\w*`, `\b` and `\s*` in record text.

**Evidence.** 0 rules / 0 records carry regex noise after regeneration; 3,982 pack tests and
7,524 asset tests pass; every record description is unique.

### 3.2 Terse concept records (113 records / 47 cell classes)

**Defect.** 113 records were shorter than 80 characters and repeated the rule title
(`In matlab, eval evaluates strings. The remedy is function handles.`).

**Fix.** 47 `recordDesc` templates rewritten (concept → consequence → remedy, with the
cell's own `{lang}/{fw}/{sink}/{safe}` placeholders). A generator-independent floor was added.

**Evidence.** 113 → **0** records under 80 chars; minimum 80, mean **183.6**; all unique;
`test-assets` guard active.

### 3.3 Identifier-boundary false positives (25 audited rules) and the wider class

**Defect.** 25 rules fired when their literal was embedded in a longer identifier
(`zzprintf(`, `myrequire(`, `module.require(`). Root causes: the `format-string` cell
(`printf` without `\b`), the `js-flag` `require` fragment, and 23 bare-identifier flag
fragments (`TelnetClient`, `_create_unverified_context`, `debug_print_backtrace|…`).

**Fix.** Two cell fragments fixed directly; 23 patched; and a generator-level rule
(`composeFlagCell` → `boundFragment`) now adds a word boundary to **each top-level
alternative that starts with a word character**, leaving punctuation-starting alternatives
(`\$"`) untouched.

**Evidence.** All 25 audited rules no longer match a `zz`-prefixed literal and still pass
their declared tests; 3,982 pack tests pass; new eval cases `EVAL-FMT-001`,
`EVAL-FMT-002`, `EVAL-REQ-001`, `EVAL-REQ-002` pin the behaviour.

### 3.4 Credential-leak scanner did not cover evaluation fixtures

**Defect.** `test-consistency` §13 exempted only `packs/secrets/**`, so the (synthetic)
credential-shaped values inside `data/eval-cases/**` had no audited allowance path.

**Fix.** `data/eval-cases/**` is exempt only when **all** hold: the file declares
`synthetic: true` **and** `testOnly: true`; the matching line is declared fixture content
(`fixture.lines`, or the observation URL/body/header); and the line carries a
synthetic-shape marker (`EXAMPLE`, placeholder, repeated-character filler). Unmarked
fixture content fails closed. Eight probes cover: marked fixture content (exempt), prose in
the same case (strict), `synthetic:false` (strict), `testOnly:false` (strict), non-eval path
(strict), unparseable file (not eligible), unmarked secrets-fixture line (failure), unmarked
eval fixture content (failure).

**Evidence.** A temporary case with a planted `AKIA…` token in `notes` made the scan fail
(exit 1, `positive: no credential shapes outside …`); removing it restored exit 0. No secret
value was committed or printed in this report.

### 3.5 DAST obsolete/over-flagging review

- `DPK-DAST-040` (Expect-CT) **already** states: deprecated header, Chromium ≥ 107, absence
  is not a current weakness, severity LOW, remediation "No action needed. Do not add the
  deprecated Expect-CT header." → verified, no change required.
- `DPK-DAST-012/013/014` (COEP/COOP/CORP) were MEDIUM with unconditional remediation.
  Now **LOW**, with explicit defense-in-depth limitations (absence is not proof of
  exploitability; COEP matters only for cross-origin isolation) and conditional remediation.
- No active exploitation, destructive request, or unauthorized probing is performed or
  recommended anywhere in the pack.

### 3.6 DAST independent-evaluation breadth

18 new observation-mode cases (headers, cookies, CORS, CSP, HSTS, content-type, error
disclosure, redirect; 10 positive, 8 negative-control) join the pre-existing DAST case and
move DAST from **1/65** to **22/65** rules referenced by independent ground truth. All
observation fixtures are synthetic objects; no request was sent.

### 3.7 Two precise detector fixes surfaced by the audit

- `DPK-SAST-415` (`.html_safe`) gained a trailing `\b`: `html_safe_safe()` no longer matches.
- `DPK-SAST-638` (`compile`) gained `(?<!\.)`: `re.compile(...)` no longer matches, while
  `compile(payload)` still does.

### 3.8 Audit-method correction (not a dataset change)

The earlier overlap figures (90 positive cross-matches / 38 CWE-conflicting / 29 negative
contradictions) **ignored rule language scoping**. Re-measured with language compatibility:
**44 positive cross-matches, 20 CWE-conflicting, 15 negative contradictions.** Of the 15,
10 involve D-13 legacy rules and 5 are rule-scoped `SAFE` declarations or generic-vs-specific
detectors. Recorded as GAP-033; no detector was merged or deleted inside this pump.
