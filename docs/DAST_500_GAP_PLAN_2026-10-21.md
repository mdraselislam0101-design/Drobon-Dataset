# DAST 500 gap plan — 2026-10-21

Status: **plan, not achievement.** DAST stands at **398 of the 500 planning target**
(79.6 %); this page records the 102 rules that remain, the families they can come from and
the one decision that is outside the dataset's control.

App reference (read-only): `mdraselislam0101-design/Drobon` @ `9360dd1`.

## 1. The two hard constraints

1. **The App is the spec.** Both App DAST engines hand the pack evaluator only the response
   body and 11 response headers (`apps/api/src/scans/dast/{rules,engine}.ts`). A rule that
   reads any other header can never fire inside the product, so it is not added — that is
   why 73 existing rules are already frozen as unreachable (`GAP-048`,
   `interop/app-dast-reachability.json`).
2. **No near-duplicates.** A new rule must ask a question no existing rule asks, and its
   positive fixture must not be a subset of an existing fixture. Rules stopped by that gate
   are listed in each batch report rather than ledgered.

Together those constraints mean the remaining 102 rules have to come from **body evidence
and `Set-Cookie` contracts**, one distinct question at a time.

### D. Markup contracts (target ~30)

host, image `srcset` from a plaintext host, `formaction` pointing at another origin,
`<input type="hidden">` carrying a password, `<option value>` carrying a token.

### E. Remaining `Set-Cookie` and forwarded-header contracts (target ~15)

`Domain` containing an underscore, `Secure` repeated, `Max-Age` with a leading `+`,
`Expires` in the past on a persistent cookie, value carrying a comma (cookie splitting at
the proxy), `SameSite` on a cookie that also sets `Partitioned` without `Secure` (a pair
contract, not yet covered), `Location` with a scheme-relative host, `Content-Type` with two
charset parameters, `X-Powered-By` naming a framework without a version.

### F. Credential shapes not yet covered (target ~8)

Limited on purpose: each one risks GitHub push protection. Viable only where the shape can
be shown with a marker (`EXAMPLE`, `redacted`) that still matches the rule: e.g. a
`postgres://` password in a query string (distinct from the userinfo form), a
`Authorization: Basic` value pasted into a page, an SMTP URL with credentials, a
pre-signed S3 URL whose expiry is in the past, an OAuth client secret in a redirect URL.

## 3. What 100 % would honestly mean

| Reading of "100 %" | Status |
|---|---|
| 500 DAST rules, each with declared tests, an eval case, provenance and a gate pass | **398/500 today**; reachable by ~4 batches of 25–30 at the current quality bar |
| 500 rules *evaluable inside the App* | **325/398 today**; cannot reach 500 while the allowlist stays at 11 headers, because 73 rules already need 47 other headers |
| "DAST is finished" as a claim | **Not claimable.** The check vocabulary is closed at seven types, so every remaining rule is another instance inside those seven; breadth is real but it is not a completeness proof |

The second row is the one that needs an owner decision: widening
`ALLOWED_RESPONSE_HEADERS` in `apps/api/src/scans/dast/rules.ts` converts 73 frozen rules
into evaluable ones in a single change, and it is the only route by which the *reachable*
count can approach the *declared* count.
