**One contract limitation found and recorded, not silently changed (SCA-CONTRACT-01).** When
the same coordinate appears twice with different `direct` flags, the first occurrence wins:

```
resolveDependencyGraph([{npm,dup,1.0.0,direct:true},  {…,direct:false}]) -> direct ["npm:dup@1.0.0"]
resolveDependencyGraph([{npm,dup,1.0.0,direct:false}, {…,direct:true}])  -> direct []
```

Both runs are internally deterministic and report the duplicate in `duplicates`, but the
*resolved classification* depends on input order. Choosing "direct wins" vs "report a
conflict" changes reachability semantics, so it needs an owner decision; no engine change was
made. This is the only SCA behaviour gap found in the audit.
