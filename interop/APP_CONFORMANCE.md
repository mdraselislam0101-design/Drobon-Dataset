## 2. DAST divergence register (App-side defect)

| Rule | Check type | Failing tests | Cause | Dataset says | App says |
|---|---|---|---|---|---|
| DPK-DAST-002 | missing-response-header | 5 | BLANK_VALUE_ARRAY | true | false |
| DPK-DAST-004 | cookie-missing-flag | 4, 5, 8 | COOKIE_MODEL_ABSENT | false | true |
| DPK-DAST-006 | cookie-missing-flag | 4, 5, 7 | COOKIE_MODEL_ABSENT | false | true |
| DPK-DAST-008 | cookie-missing-flag | 3, 4, 5 | COOKIE_MODEL_ABSENT | false | true |
| DPK-DAST-096 | response-header-matches | 3 | ARRAY_JOIN_CROSS_VALUE | false | true |
| DPK-DAST-100 | response-header-matches | 6 | ARRAY_JOIN_CROSS_VALUE | false | true |
| DPK-DAST-116 | response-header-matches | 4 | ARRAY_JOIN_CROSS_VALUE | false | true |
| DPK-DAST-155 | response-header-matches | 2 | ARRAY_JOIN_CROSS_VALUE | false | true |
| DPK-DAST-190 | response-header-matches | 2 | ARRAY_JOIN_CROSS_VALUE | false | true |

Total: **15 divergences on 9 rules**, out of 1,419 declared DAST tests.

Causes (from `interop/app-conformance.json → causes`):

- **COOKIE_MODEL_ABSENT** — The App parses Set-Cookie with a string split and compares whole attributes case-insensitively. This repository models the browser: a discarded header stores no cookie, Secure/HttpOnly ignore their value (Secure=0 is the flag on), and SameSite only counts with a recognised Strict/Lax/None value (scripts/lib/set-cookie.mjs).
- **BLANK_VALUE_ARRAY** — The App joins repeated header values with ", " and trims the result, so "present but every value blank" never looks empty. This repository treats an all-blank header as absent (docs/PACKS.md, missing-response-header).
- **ARRAY_JOIN_CROSS_VALUE** — The App evaluates a repeated header as one ", "-joined string, so a pattern can match across a value boundary. This repository evaluates the header semantics per docs/PACKS.md.

Direction of the fix: **the App ports this repository**, not the other way round.
The dataset keeps the browser-accurate cookie model (`scripts/lib/set-cookie.mjs`),
treats an all-blank header as absent, and never matches a pattern across a repeated
header value boundary. Declared tests are unchanged by this register.

## 4. App loader checklist (docs/PACKS.md)

| # | Requirement | Status | App evidence | Gap |
|---|---|---|---|---|
| 1 | Validate packs with this repo's validator semantics; fail closed on unknown schema, field or check type | **PARTIAL** | apps/api/src/external/service.ts (shape guard: string schemaVersion + string id only) | Unknown fields are unchecked and an unknown DAST check type silently evaluates to false instead of refusing the pack. |
| 2 | Gate SAST rules by the App language catalog | **DONE** | apps/api/src/scans/sast/engine.ts (rule.languages.includes(file.family)) | Implemented; the residual reachability gap is a catalog-coverage problem, measured above. |
| 3 | Re-run bounded-time ReDoS regression over all pack patterns | **MISSING** | apps/api/src/external/packProvider.ts (compiles patterns, no budget) | No pathological-input budget runs over the pack patterns before they go live. |
| 4 | Execute every rule's declared examples at load and refuse failing packs | **MISSING** | apps/api/src/external/packProvider.ts (converts only, never runs rule.tests) | The direct cause of the DAST divergences recorded above: a rule whose declared tests disagree ships silently. |
| 5 | Redact secrets evidence per redact / matchOnlyEvidence before persisting | **DONE** | apps/api/src/scans/secrets/engine.ts (positional redaction, fail-closed fallback) | Implemented and covered by the App secrets suite. |
| 6 | Surface pack id + version in scan metadata so findings trace to data versions | **MISSING** | apps/api/src/external/service.ts (pack.json is never read) | A finding cannot be traced to the dataset version that produced it. |

Result: 2 done · 1 partial · 3 missing. Step 4 (execute
declared tests at load) is the structural cause of section 2: a loader that ran
each rule's own `tests[]` would have refused the disagreeing pack instead of
shipping it.

## 7. What this register does not say

- It is not a claim that the Dataset works end-to-end in the App: reachability,
  loader conformance and the remediation surface are still open (see
  `docs/DATASET_COMPLETION_LEDGER.md`).
- It does not change any declared pack test, rule, or status in this repository.
- It is measured against one pinned App commit, not against a released App.
